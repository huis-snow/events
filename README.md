# 길드 오락실

길드 이벤트 한 회차를 방 하나에서 운영하는 실시간 게임 페이지입니다. 참가자는 처음 한 번만 이름을 등록하고, 진행자가 고른 게임을 차례로 플레이하며, 각 게임에서 받은 이벤트 포인트를 최종 결산까지 누적합니다.

빌드 과정 없는 정적 HTML/CSS/JavaScript 앱이며 GitHub Pages의 저장소 루트에서 배포합니다.

## 이벤트 진행 흐름

```text
이벤트 방 생성 → 참가자 입장 → 게임 선택 → 게임 진행
       ↑                              ↓
최종 결산 ← 다음 게임 또는 종료 ← 결과 확정·종합 랭킹
```

- 이벤트 코드와 초대 링크는 모든 게임에서 동일합니다.
- 참가자 이름과 종합 점수는 게임이 바뀌어도 유지됩니다.
- 모든 게임은 내부 원점수와 무관하게 이벤트 포인트 `1위 10P · 2위 8P · 3위 6P · 4위 5P · 5위 4P · 그 외 참가 2P`로 환산합니다.
- 같은 게임 점수는 같은 순위와 같은 이벤트 포인트를 받습니다.
- 게임 결과는 진행자가 확정할 때 참가자 합계와 점수 원장에 한 번만 기록됩니다.
- 진행 중 들어온 참가자는 0P로 종합 순위에 등록되고, 현재 게임은 관전한 뒤 다음 게임부터 참가합니다.
- 준비 중 들어온 참가자는 현재 게임부터 참가할 수 있습니다.
- 이벤트가 끝나면 참가 접수를 닫고 최종 공동 순위를 표시합니다.

## 게임

- [다 같이 빙고](./bingo/) — 참가자마다 `1~50` 중 중복 없는 숫자 25개로 5×5 빙고판을 만들고, 방장이 항아리에서 중복 없이 숫자를 뽑으면 모든 화면이 실시간으로 체크되는 게임
- [눈치 숫자](./nunchi-number/) — 참가 인원에 맞는 범위에서 숫자를 몰래 고르고, 역순·높은 숫자·랜덤 현상금 중 선택한 규칙대로 점수를 얻는 실시간 심리전
- [초성 탈출](./chosung-escape/) — 진행자가 준비한 한국어 정답을 글자 수·초성·모음·한 글자와 설명 순으로 적게 보고 맞힐수록 높은 점수를 얻는 실시간 단어 레이스

각 게임 주소를 직접 열면 종합 점수와 무관한 연습용 단독 방으로도 사용할 수 있습니다.

## 폰트

기본 UI에는 넥슨이 제공한 메이플스토리 서체 Light·Bold를 사용합니다. 메이플스토리 서체의 지적 재산권을 포함한 모든 권리는 (주)넥슨코리아에 있으며, 자세한 사용 조건은 [공식 서체 페이지](https://maplestory.nexon.com/Media/Font)에서 확인할 수 있습니다.

## 빙고 규칙

- 중앙 무료 칸 없이 25칸 모두 숫자를 입력하며 한 판에서 같은 숫자를 두 번 사용할 수 없습니다.
- 가로 5줄, 세로 5줄, 대각선 2줄의 총 12줄을 계산합니다.
- 항아리 자동 추첨은 아직 나오지 않은 숫자 중 하나만 뽑으므로 중복되지 않습니다.
- 기존 `/주사위 50` 결과 직접 입력도 사용할 수 있으며 이미 나온 숫자는 기록하지 않습니다.
- 기본 승리 조건은 3빙고이며 게임 선택 때 4빙고·5빙고로 바꿀 수 있습니다.
- 같은 추첨 숫자로 여러 명이 목표에 도달하면 모두 공동 우승입니다.
- 게임을 시작하면 참가자 빙고판이 잠기며 방장만 호출 숫자 입력·취소·종료를 할 수 있습니다.

## 눈치 숫자 규칙

- 카드 수는 `max(4, ceil(게임 시작 참가자 수 × 3/4))`로 자동 결정됩니다.
- 진행자는 숫자 선택 시간을 10초·15초·20초·30초 중 고르며 기본값은 20초입니다.
- 제한 시간이 끝나면 추가 선택이 차단되고 연결된 참가자 화면에서 라운드가 자동 공개됩니다.
- 모든 참가자가 숫자 하나를 비밀리에 제출한 뒤 방장이 한꺼번에 공개합니다.
- 같은 숫자를 고른 사람은 모두 탈락합니다.
- `역순 포인트`는 1부터 N 카드에 N점부터 1점을 배치하고 가장 작은 단독 숫자의 참가자가 득점합니다.
- `높은 숫자 보상`은 가장 작은 단독 숫자를 고른 참가자가 선택한 숫자만큼 득점합니다.
- `랜덤 현상금`은 매 라운드 1부터 N점을 무작위로 다시 배치하며 모든 단독 카드가 표시 점수를 얻습니다.
- 기본 라운드가 끝난 뒤 최고 게임 점수가 동점이면 공동 선두만 서든데스를 계속합니다.
- 공개 전 선택값은 본인만 읽을 수 있고 다른 화면에는 제출 여부만 표시됩니다.
- 카드 비율을 바꿀 때는 고정 시드 시뮬레이터로 득점률·0점률·1위 동점률을 기존 규칙과 비교합니다.

## 초성 탈출 규칙

- 진행자가 한국어 정답·카테고리·마지막 설명 힌트를 5–7개 준비합니다.
- 정답은 진행자만 읽을 수 있는 비공개 문서에 저장되고 참가자에게는 단계별 힌트만 전달됩니다.
- `글자 수 5점 → 초성 4점 → 가운데 모음 3점 → 한 글자·설명 2점` 순으로 힌트가 열립니다.
- 참가자는 동시에 정답을 제출하며 오답 뒤에는 3초 후 다시 시도할 수 있습니다.
- 문제별 획득 점수를 합산해 게임 순위를 정한 뒤 공통 이벤트 점수표로 환산합니다.

## Firebase

작은 도구함의 Firebase와 분리된 전용 프로젝트를 사용합니다.

- Firebase 프로젝트: `huis-snow-events`
- 웹 앱: `events-web`
- Firestore 리전: `asia-northeast3` (서울)
- 인증: 익명 로그인
- 이벤트 컬렉션: `eventRooms/{eventId}`
- 이벤트 하위 컬렉션: `participants` · `matches` · `ledger`
- 게임 컬렉션: `bingoRooms/{roomId}` · `nunchiRooms/{roomId}`
- 초성 탈출 컬렉션: `chosungRooms/{roomId}` (`secrets` · `guesses` 하위 컬렉션)

Firebase 웹 설정은 프로젝트를 식별하는 공개 설정이며 서비스 계정 키가 아닙니다. 진행자 권한은 이벤트를 만든 브라우저의 익명 Firebase UID에 연결되므로 실제 이벤트에서는 일반 브라우저 창을 사용하고 사이트 데이터를 지우지 않아야 합니다.

보안 규칙과 인증 설정 배포:

```bash
npm run firebase:deploy
```

보안 규칙은 로그인 사용자만 코드를 아는 방을 직접 읽게 하고 전체 방 목록 조회를 차단합니다. 참가자 본인만 이름과 게임 제출을 기록할 수 있으며 이벤트 진행, 게임 상태 변경, 결과 확정, 종합 점수 반영은 진행자에게만 허용합니다.
